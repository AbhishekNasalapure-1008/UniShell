# UniShell — Command and System Call Map

Every feature in UniShell is traceable to the exact command or C function it
uses, the file and function that uses it, the reason it is used, and the output
a student should expect. **This file is updated at the end of every phase.**

| Feature | Command or C function | File and function | Why it is used | Expected output |
|---|---|---|---|---|
| Scaffold build (Phase 2) | `make all` | `Makefile` target `all` | Compiles every `c_programs/*.c` into `bin/` without touching sources | `[make all] no C sources in c_programs/ yet - nothing to compile` until C files are added |
| Scaffold verification (Phase 2) | `bash tests/test_00_scaffold.sh` | `tests/test_00_scaffold.sh` | Proves folders, write access, toolchain and line endings are correct before any feature relies on them | PASS/FAIL lines, then `Scaffold self-test result: N passed, 0 failed` |
| Test runner (Phase 2) | `make test` | `Makefile` target `test` | Runs every `tests/test_*.sh` and fails the build if any test fails | `=== RESULT: ALL TESTS PASSED ===` |
| Load shared helpers (Phase 3) | `source lib/common.sh` | `unishell.sh` → `main` | Loads colours, input handling, the sandbox guard and logging into the running shell so every module shares one implementation | No output; the helper functions become available |
| Read a menu choice (Phase 3) | `read -r` | `lib/common.sh` → `ask_choice` | Reads one line exactly as typed, then validates it, so nothing typed is ever treated as a command | Prompt `Enter your choice (0-10): ` and a validated number in `$UNISHELL_CHOICE` |
| Validate the choice (Phase 3) | `case` with `*[!0-9]*` | `lib/common.sh` → `ask_choice` | Accepts digits only and rejects every other character, so `abc`, `-1` or a whole command line never passes through | `That is not a number. Please type digits only.` then it re-asks |
| Range check (Phase 3) | `$((10#$answer))` and `-lt`/`-gt` | `lib/common.sh` → `ask_choice` | Forces base 10 (so `08` is 8, not invalid octal) and keeps the answer inside `min..max` | `Please choose a number from 0 to 10.` then it re-asks |
| Dispatch a choice (Phase 3) | `case` on `$1` | `unishell.sh` → `handle_choice` | Maps the number to a fixed function name; only built-in names can be called, so typed text can never run | Calls `run_module <key> <title> <phase>` |
| Check a module exists (Phase 3) | `declare -F` | `unishell.sh` → `run_module` | Confirms `module_<key>` is really defined before calling it, instead of failing mid-run | Truthful `... is not implemented yet.` plus its scheduled phase |
| Reject unsafe names (Phase 3) | `case` guards | `lib/common.sh` → `is_safe_name` | Refuses empty names, `.`, `..`, a leading `-`, any `/`, spaces and control characters so a name cannot escape the sandbox | Returns non-zero and prints nothing |
| Confirm containment (Phase 3) | `realpath -m` | `lib/common.sh` → `check_inside_sandbox` | Resolves `..` and symlinks once, then checks the real path still starts with the sandbox, so no destructive demo can leave it | Returns 0 only for a path inside `./sandbox` |
| Record activity (Phase 3) | `date '+%Y-%m-%d %H:%M:%S'` and `>>` | `lib/common.sh` → `log_activity` | Appends one timestamped line so earlier entries are never lost; user-typed text is never written | One new line in `logs/activity.log` |
| Leave cleanly on Ctrl-C (Phase 3) | `trap` | `unishell.sh` → `on_interrupt` | Restores normal terminal behaviour and exits with the conventional 130 instead of dying mid-menu | `Interrupted. Leaving UniShell cleanly.` |
| Colour only on a terminal (Phase 3) | `[ -t 1 ]` | `lib/common.sh` | Keeps colours for a human but plain text in pipes and log files, so captured test output stays readable | No escape sequences when output is redirected |
| Common helper tests (Phase 3) | `bash tests/test_01_common.sh` | `tests/test_01_common.sh` | Unit-tests name safety, sandbox containment, logging and input validation | PASS/FAIL lines, then `common.sh unit test result: N passed, 0 failed` |
| Menu tests (Phase 3) | `bash tests/test_02_menu.sh` | `tests/test_02_menu.sh` | Drives the real menu with scripted input to check navigation, invalid input, exit codes and injection safety | PASS/FAIL lines, then `menu test result: N passed, 0 failed` |
| Harvest one entry (Phase 4) | `awk '/^### /'` and `awk -v want` | `modules/commands.sh` → `cmdlib_entries`, `cmdlib_show` | Reads the human-readable library without executing any of it: one block per command name | The list of names, or the seven fields of one command |
| Look up a command (Phase 4) | `for` over the names from `awk` | `modules/commands.sh` → `cmdlib_has` | Confirms a typed name really exists in `data/command_library.txt` before printing anything | A block for a known name, or `There is no entry for ...` |
| Explain a command (Phase 4) | `printf`, `is_safe_name` | `modules/commands.sh` → `cmdlib_explain`, `cmdlib_privileged` | Validates the typed name **before** echoing it, so no control characters reach the terminal; `passwd` and `su` are only described | Purpose, syntax, example, output, uses, notes and syllabus module |
| Safe builtin demos (Phase 4) | `echo`, `printf`, `date`, `cal`, `who`, `type`, `read`, `test`, `set`, `shift`, `trap` | `modules/commands.sh` → `cmdlib_demo_*` | Runs real commands; `readonly`, `set`/`shift` and `trap` run inside subshells so UniShell itself is untouched | Live output with a short explanation after each demo |
| Create practice files (Phase 4) | `mkdir -p`, `touch`, `>`, `chmod` | `modules/files.sh` → `files_make_demo_tree`, `perm_make_demo` | Builds the sample tree and practice file **inside `./sandbox`** so demos have something real to work on | `sandbox/demo/`, `sandbox/notes.txt`, `sandbox/perm_demo.txt` |
| List a directory (Phase 4) | `ls`, `ls -a`, `ls -l`, `ls -R` | `modules/files.sh` → `files_demo_list` | Shows plain, hidden, long and recursive listings of the sandbox | The directory contents, including `.` and `..` under `-a` |
| Show paths and errors (Phase 4) | `pwd`, `cd` (in a subshell) | `modules/files.sh` → `files_demo_paths` | Explains absolute vs relative paths and proves a failed `cd` returns status 1 without stopping UniShell | The absolute path, then `cd failed, as expected ... (exit status 1)` |
| Copy and move safely (Phase 4) | `cp`, `mv` | `modules/files.sh` → `files_demo_copy_move` | Both names pass `is_safe_name` and are resolved with `sandbox_path` before either command runs | `cp created the copy.` and, if chosen, `mv renamed the copy.` |
| Remove safely (Phase 4) | `realpath -m`, `rmdir`, `rm` | `modules/files.sh` → `files_demo_remove` | Two independent checks (`is_safe_name` then `check_inside_sandbox`) plus a confirmation; `rmdir` for directories, never `rm -r` on a user name | `rm removed the file.` or a clear refusal message |
| Reset the sandbox (Phase 4) | `find -mindepth 1` and `rm -rf` | `modules/files.sh` → `files_demo_reset` | Lists every entry inside the sandbox and re-checks each one before deleting; `.gitkeep` and the sandbox directory itself are never in the list | `Reset finished. Entries removed: N` |
| Command library tests (Phase 4) | `bash tests/test_03_commands.sh` | `tests/test_03_commands.sh` | Proves all 28 commands are documented with the fixed fields and that typed payloads are never executed | PASS/FAIL lines, then `module 1 test result: N passed, 0 failed` |
| File management tests (Phase 4) | `bash tests/test_04_files.sh` | `tests/test_04_files.sh` | Drives the real menu to create, copy, remove and reset, and proves removal cannot escape the sandbox | PASS/FAIL lines, then `module 2 test result: N passed, 0 failed` |
| Read permissions (Phase 5) | `ls -l`, `stat -c '%a %A %U %G'` | `modules/permissions.sh` → `perm_line`, `perm_demo_read` | Shows the ten characters of `ls -l` and the matching numeric mode of the practice file | The long listing plus `numeric mode = 644  symbolic = -rw-r--r--` |
| Symbolic and numeric `chmod` (Phase 5) | `chmod u+x`, `chmod g-w`, `chmod o=r`, `chmod 600/755/644` | `modules/permissions.sh` → `perm_demo_symbolic`, `perm_demo_numeric` | Every change is made to `sandbox/perm_demo.txt` and printed with `ls -l` and `stat` afterwards | The mode before and after each step |

| Explain `chown` (Phase 5) | (nothing is executed) | `modules/permissions.sh` → `perm_demo_chown` | Teaches ownership and group changes without running anything, because changing an owner needs root | A text explanation; the owner of the practice file does not change |
| Permission tests (Phase 5) | `bash tests/test_05_permissions.sh` | `tests/test_05_permissions.sh` | Proves `chmod`, `umask` and `stat` really work on this filesystem and that `chown` is never executed | PASS/FAIL lines, then `module 3 test result: N passed, 0 failed` |
| Streams and redirection (Phase 5) | `>&2`, `>`, `>>`, `<`, `2>`, `2>&1` | `modules/text_processing.sh` → `txt_demo_streams`, `txt_demo_redirection` | Explains fd 0/1/2 and shows each operator writing into `./sandbox` | The redirected files `sandbox/redirect.txt` and `sandbox/redirect.err` |
